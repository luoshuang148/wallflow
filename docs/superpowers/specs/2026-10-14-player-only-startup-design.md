# Player-only login startup

The user clarified that login startup must launch only the playback program, never briefly boot management. Preserve no menu icon after ordinary management quit, Settings complete exit, default enable with saved opt-out, and all user data.

Builder decisions: the player exposes a small startup-control CLI before entering AppKit or acquiring its playback lease. This CLI runs SMAppService.mainApp from the player bundle and returns a bounded JSON reply with its own bundle ID/path and OS status. Management uses the CLI to configure the player's own login item. Main-app service registration does not immediately start a helper or kill playback on unregister, unlike directly registering the long-lived player as an SM login helper. Verify the real system registration points to the player before claiming completion.

Migrate enabled legacy management registration by registering the player first and only then removing the manager's registration. Run migration even when the prior one-time default marker is already set; preserve off choices. Failed migration remains visible/retryable and does not remove a working legacy item. Treat legacy requiresApproval as potentially revoked consent: remove the inactive legacy record and preserve off without registering a fresh identity. Disable attempts both records; failed disable is retryable without re-enabling migration. A later explicit system enable remains authoritative. Retain old login-event classification only as compatibility for a legacy registration that fails migration; successful migration leaves no manager startup item. Version0.9.3/build22, macOS14+, no dependencies, no GitHub release changes.
